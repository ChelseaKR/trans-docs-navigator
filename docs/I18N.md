# i18n status: IN SCOPE

`trans-docs-navigator` is an **in-scope** repo under
[`INTERNATIONALIZATION-STANDARD.md`](https://github.com/ChelseaKR/portfolio-standards) §1:
a public, safety-critical, bilingual (EN/ES) legal-document navigation surface serving
Spanish-dominant California populations. i18n is **required**, not optional.

This document records which of the standard's AUTO-GATES (§4) are live, which are
**N/A-until-used**, and which are deferred to a later phase.

## Catalog format — typed TS `LocaleBundle`

Every user-visible string lives in a typed `LocaleBundle` module, one per language:

| File | Role |
|---|---|
| `src/i18n/types.ts` | `LocaleBundle` interface — UI chrome, doc titles/labels, form-field labels, generator scaffolding, legal-page copy, SEO metadata |
| `src/i18n/en.ts` | English bundle (reference locale) |
| `src/i18n/es.ts` | Spanish bundle |
| `src/i18n/index.ts` | Locale registry (`SUPPORTED_LOCALES`, `t(lang)`, `asLanguage()`) |

Because the bundles implement a shared interface, the **TypeScript compiler already
enforces key parity for known keys**; the runtime gate below (G6) is the fail-closed rail
that also catches empty/whitespace-only translations and structural drift.

This is the chosen container for this repo. The standard's normative message layer for new
TS work is **MF2** (`@messageformat/core` + `@formatjs`); adopting it here is tracked under
"MF1→MF2 audit" below and is **not** part of the current mechanical-gates phase.

## Live AUTO-GATES (merge-blocking, wired into `make verify` == CI)

| # | Gate | Where | Status |
|---|---|---|---|
| **G1** | UTF-8 encoding — every tracked text file is `utf-8`/`us-ascii` | `scripts/i18n-utf8.ts` (`make i18n-utf8`, step 12/19) | **live** |
| **G3** | BCP 47 tag validity — every authored locale tag well-formed + registry-valid via `Intl` | `scripts/i18n-bcp47.ts` (`make i18n-bcp47`, step 13/19) | **live** |
| **G4** | HTML root `lang` (WCAG 3.1.1 A) — `html-has-lang` + `html-lang-valid` | `.pa11yci.json` axe/htmlcs WCAG2AA (`a11y-browser` CI job); the static `scripts/a11y-lint.ts` also asserts `<html lang>` presence on every rendered page | **already present** |
| **G6** | EN/ES key-parity — `keys(en) == keys(es)`, no empty translations | `scripts/i18n-parity.ts` (`make i18n`, step 14/19) | **already present** |
| **G9** | Pseudolocale overflow — the key routes render an `en-XA` pseudolocale (~40% expansion, accents, `⟦…⟧`) on desktop + mobile with no clipping, ellipsis/nowrap truncation, or horizontal scroll | `scripts/i18n-pseudo.ts` (generator) + `tests/e2e/i18n/pseudo-overflow.spec.ts` (Playwright) via `make i18n-overflow`, step 19/19 | **live (new)** |
| **G10** | Logical-CSS (static) — inline-axis physical CSS (`left`/`right`, `margin/padding/border-*`, `text-align`) is rejected in favour of logical properties, so the layout mirrors under RTL | `stylelint.config.js` (`stylelint-use-logical`) over the extracted stylesheet, `make i18n-logical-css`, step 15/19 | **live (new)** |

`make verify` runs the same blocking pipeline CI runs (no local/CI drift). G1/G3/G6/G10
run offline and are deterministic; G9 drives a real browser (Playwright) and is wired into
`make verify` as the final step.

## Frontend depth gates — G9 pseudolocale overflow + G10 logical-CSS

These replicate a validated pilot from a sibling project, adapted to this repo's
**server-rendered** architecture (no client i18n instance; the locale is chosen by
`?language=` and resolved through `t()`/`asLanguage()` in `src/i18n/index.ts`).
`?lang=` is also accepted as an alias on incoming requests (`languageParam()` in
`api/router.ts`) so a typed or shared link built from the more common web convention
doesn't silently fall back to English; every link this app generates still emits the
canonical `?language=`.

**G9 — pseudolocale overflow (live).** `scripts/i18n-pseudo.ts` deterministically transforms
the English `LocaleBundle` (`src/i18n/en.ts`) into an `en-XA` pseudolocale: every Latin letter
is accented, text is expanded ~40% to mimic longer locales, and each string value is wrapped in
`⟦ … ⟧`. The bundle's **generator/SEO functions**, `{…}` interpolation placeholders, and the
legal pages' **HTML tags/entities** are protected verbatim — only literal visible text is
transformed, so the pseudo bundle stays a valid, runnable `LocaleBundle`. The generated JSON is
a **test artifact**: git-ignored and written OUTSIDE `src/i18n/` (`tests/e2e/i18n/`), so the G3
tag and G6 parity gates never treat it as a shipping locale.

The overflow spec (`tests/e2e/i18n/pseudo-overflow.spec.ts`, Playwright) drives the key routes
(intake, checklist, packet, answer, form-fill, legal prose) under `?language=en-XA` on desktop
+ Pixel-7 mobile and asserts `scrollWidth ≤ clientWidth` on the page and key containers, plus no
ellipsis/nowrap truncation (sr-only excluded). The pseudolocale is registered in the resolver
**only** behind a build-time test flag: the test server (`tests/e2e/i18n/pseudo-server.ts`) sets
`TDN_I18N_TEST_HOOKS=1` and calls the test-only `registerTestLocale()` before booting; the
production server (`api/server.ts`) never does, so `?language=en-XA` falls back to English and
`en-XA` can never ship (proven by `tests/i18n-pseudo-hook.test.ts`). The `/guide` surfaces are
excluded from the spec because they key a hardcoded state-name map strictly by the shipping
`Language` union; this is inert in production (only en/es are ever resolved) and their layout is
already exercised by `/checklist` + `/terms`.

**G10 — logical-CSS (static gate live).** `stylelint.config.js` runs `csstools/use-logical`
(`stylelint-use-logical`) scoped to the **inline (writing-direction) axis** via `except` — the
block axis (`top`/`bottom`, `*-block-*`) and box sizing (`width`/`height`) are intentionally left
physical because they do not flip under RTL. The app stylesheet is the typed `STYLE` template in
`src/render.ts` (served at `/assets/app.css`); `make i18n-logical-css` extracts it to a
git-ignored artifact and lints that (fix findings in `render.ts`). This change converted **2**
physical inline declarations to logical (`.skip` / `.skip:focus` `left` → `inset-inline-start`);
LTR rendering is byte-identical (`inset-inline-start` == `left` in LTR).

**Deferred (locked): ar/he RTL mirror smoke.** The dynamic `dir="rtl"` Playwright mirror check
that verifies the runtime flips correctly is deferred until an RTL locale actually ships. Until
then, the G10 static gate keeps new physical inline CSS from landing, so the layout stays
RTL-ready. When ar or he is added, wire the mirror smoke alongside G9.

## N/A-until-used gates

| # | Gate | Why N/A here |
|---|---|---|
| **G12** | CLDR/tzdata version pin (`@formatjs`/`@messageformat` ≥ 48.2, tzdata ≥ 2026a) | **N/A-until-used.** The frontend does **no `Intl`-based number/date/currency formatting** and ships no `@formatjs`/`@messageformat` runtime dependency: costs and dates are rendered as already-formatted strings from the corpus, and answer scaffolding uses plain templated `LocaleBundle` strings. There is no CLDR-backed formatting surface to pin. **The moment the UI adds `Intl.NumberFormat`/`Intl.DateTimeFormat` or a FormatJS/MessageFormat runtime, G12 becomes live** and the ≥ 48.2 / tzdata ≥ 2026a pins per §10 must be asserted in `package.json`. |
| G7 | PO compilation (`msgfmt`) | N/A — gettext/`.po` is the Python container; this repo uses TS `LocaleBundle`. |
| G8 | XLIFF schema validity | N/A — no committed `.xlf` (no TMS round-trip yet). |
| G11 | `Vary: Accept-Language` | N/A-until-negotiated — locale is chosen by explicit `?language=` param, not `Accept-Language` content negotiation. Becomes live if/when the server negotiates by header (§6). **`Content-Language` is a separate, live half of G11** (added 2026-07-05): every `text/html` response carries `Content-Language: <resolved lang>` (`api/server.ts`, computed with the same `asLanguage()` resolution the page rendered with), regardless of selection mechanism — it declares the actual language of the delivered content even though there is no header-based negotiation to `Vary` on. |

## Deferred to a later phase (NOT in this change)

- **G2 — no-hardcoded-UI-strings extraction.** `formatjs extract` + `eslint-plugin-formatjs`
  `no-literal-string` ratchet. Requires adopting the FormatJS extraction toolchain across
  `src/`/`api/` renderers; deferred to a dedicated phase. Until then, key parity (G6) plus
  the typed `LocaleBundle` interface keep the catalog complete for the strings that are
  already externalized.
- **G5 — placeholder parity.** ICU/interpolation placeholder-set equality across locales.
  Deferred to a dedicated phase; today the typed `LocaleBundle` + G6 key-parity keep the
  externalized strings structurally aligned, and G9's pseudolocale surfaces any placeholder
  that fails to render. Tracked in `docs/ROADMAP.md`.

  (**G9 pseudolocale overflow** and **G10 logical-CSS (static)** are now **live** — see the
  Live AUTO-GATES table and the "Frontend depth gates" section above. The **ar/he RTL mirror
  smoke** is the only frontend i18n item still deferred.)

## MF1 → MF2 audit (§9) — Phase-2 item

The standard requires any repo with existing ICU **MF1** resources to ship
`MIGRATION_MF2.md` and to reject new MF1 syntax after plan adoption.

**Status: audit pending (Phase 2 — not performed in this change.)** Preliminary observation:
the catalog uses typed TS strings with simple `{name}`-style placeholders and a few template
functions (e.g. `progressTemplate`, `generator.costAbout(...)`), **not** `react-intl`/ICU
MessageFormat — so there are likely **no MF1 message resources to migrate**. The formal §9
audit and the decision to either commit `MIGRATION_MF2.md` or record "no MF1 present" is
deferred to a later phase.

## Upgrade cadence

CLDR/ICU tracking cadence (§10): re-evaluate on each major CLDR release (next ≥ 49) and
whenever G12 graduates from N/A-until-used to live. Dependabot opens dependency-bump PRs;
the i18n gates prove non-breaking.
